# CLAUDE.md — faq-bot

Описание проекта (что и зачем): @description.md

## Стек
- Python 3.11+
- aiogram 3 — работа с Telegram
- API нейросети (по умолчанию Claude) — генерация ответов
- pypdf — чтение PDF из базы знаний
- python-dotenv — загрузка ключей из `.env`
- pytest — тесты

## Структура
```
faq-bot/
├── bot.py              # точка входа и обработчики сообщений Telegram
├── knowledge_base.py   # чтение .txt и .pdf из knowledge/
├── llm.py              # запрос к нейросети, системный промпт
├── knowledge/          # база знаний — только чтение
├── tests/              # pytest, без реальных сервисов
├── requirements.txt
├── pytest.ini
├── .env.example        # шаблон ключей без настоящих значений
└── .env                # настоящие ключи, в git не попадает
```

## Команды
- Установка: `python -m venv .venv && source .venv/bin/activate && pip install -r requirements.txt`
- Запуск бота: `python bot.py`
- Тесты: `pytest`

## Правила
- **`knowledge/` только читать.** Никогда не изменять, не удалять и не переименовывать файлы базы знаний.
- **Ключи только в `.env`.** Не выводить токены и ключи в логи, ошибки и ответы бота. Не коммитить `.env`.
  Новый ключ — добавить его название в `.env.example` с пустым значением.
- **Ответы только по базе знаний.** Системный промпт нейросети обязан запрещать выдумывать
  цены, сроки и обещания. Если ответа в базе нет — бот говорит об этом и предлагает связаться с менеджером.
  Любое изменение промпта проверять на вопросе, ответа на который в базе нет.
- **Без векторных баз и лишней сложности.** Текст базы знаний передаётся нейросети целиком.
  Новые библиотеки — только если без них не обойтись.
- **Тесты без реальных сервисов.** В тестах не обращаться к настоящему Telegram и API нейросети —
  подменять их заглушками (mock). Тесты не должны тратить деньги и требовать ключей.
- **Модель нейросети задаётся в `.env`**, а не прописывается в коде — чтобы её можно было сменить без правки кода.
